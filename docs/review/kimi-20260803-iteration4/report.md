## 2. 本轮发现并修复的真实缺陷

### 2.1 浏览器代理丢失幂等键

前端 `createCampaign` 已发送 `Idempotency-Key`，但 Next.js BFF 代理只转发
`content-type`、`accept` 和服务端会话令牌，导致幂等键在真实浏览器链路中丢失。

直接后果：

- 首次创建在服务端成功，但浏览器在 60 秒先超时。
- 用户点击“重试”后生成第二份相同草稿。
- 实测重复 Campaign：`acf80116-…` 与 `b12471bd-…`。

修复后：

- BFF 通过显式安全白名单转发 `idempotency-key`。
- 浏览器 Cookie、浏览器自带 Authorization 和任意请求头仍不会透传。
- Kimi 在真实登录态下连续发送两次同键 POST，均返回
  `48e2c110-0487-5f81-a5f3-a21bc2902858`。

### 2.2 上游模型取消可能延迟到 60 秒

普通 `asyncio.timeout()` 会等待部分 SDK 完成取消清理，因此“25 秒超时”仍可能表现为
60 秒以上。现改为硬截止：

- 评估阶段最多 12 秒，使用快模型和 1200 token 上限。
- 起草阶段最多 25 秒。
- 截止后不等待上游取消清理，立即返回确定性的可用提纲。
- 兜底提纲包含 3 条假设、具体画像、3 条筛选题、6 个开放问题、2 条可量化成功标准和 5 条方法/体验建议。
- 中英文兜底均保留语言、分支追问、CIT、错误容忍、移动端、会话连续性和招募偏差提醒。

### 2.3 等待过程缺少可解释反馈

旧体验只有“正在思考”，超过一分钟后直接显示超时。新体验展示：

1. 正在理解研究目标。
2. 正在生成访谈提纲。
3. 正在加载完整提纲。
4. 正在更新访谈提纲。
5. 每秒更新可见耗时。
6. 超过 20 秒时明确说明上游较慢、请求仍安全、重试不会生成重复问卷。

状态采用独立 `role="status"` 和礼貌 live region；视觉秒表不逐秒打扰屏幕阅读器。
