## 2. 基线问题与最终解法

### 2.1 从“应用面板”变成“桌面上的研究手稿”

基线右侧是与聊天栏近似同色的巨大空面板，完成后人物画像和每个题目又各自拥有完整圆角边框。
这会让用户感知停留在“表单生成器”，而不是“正在共同写一份研究手稿”。

最终结构：

1. `desk` 负责环境深度，仅用极低对比的暖灰渐变和 1.8% 颗粒。
2. `sheet` 是一张 860px 的连续纸面，2px 纸张圆角，没有应用卡片感。
3. `research task` 是全文唯一的强调面，只保留一条 2px 左侧绿色规则。
4. 人物画像、假设、筛选条件、题目和成功标准回归文档块。
5. 题目共享一个列表边界，使用行间细线，不再每题一张卡。
6. 发布渠道共享一个成组容器，状态通过复选框和底色表达。

这套边界系统比 Notion 的通用文档块多了一层研究语义，同时保留了它最重要的克制。

### 2.2 从“突然出现”变成“结构逐渐成形”

基线等待期右侧画布为空。用户只能从聊天栏判断系统是否还活着，完成内容会整块跳入页面。

最终生成态：

- 状态文案和真实耗时位于纸张上沿。
- 标题、目标、研究任务和问题区按最终布局先形成。
- 不使用扫光 shimmer，避免廉价的加载器感。
- 只有 2px 写入光标持续呼吸，其余区域只入场一次。
- 完成态区块按阅读顺序使用 `opacity + translateY` 浮现。
- 首次浮现延迟从 40ms 到 570ms，运动曲线统一为
  `cubic-bezier(0.22, 1, 0.36, 1)`。
- 更新提示在 1800ms 后归于平静，不让绿色边轨变成永久装饰。

骨架与最终文档使用相同空间结构，因此内容接管时没有位置跳跃。这是本轮相对 Notion
最明确的优势：Notion 的块编辑非常成熟，但没有为“AI 生成一份完整研究方案”提供同等强度的叙事反馈。

### 2.3 从“桌面双栏缩小版”变成真实移动工作流

基线 390px 下仍保留 380px 设计聊天栏，右侧画布只是被挤出视口。视觉上像正常，
但不是响应式布局。

最终移动规则：

- 问卷创建前：聊天占满可用工作区，画布隐藏。
- 问卷创建后：聊天收为 48px 横向召回条，讨论指南进入主屏。
- 展开聊天时：占据 42dvh，仍保留文档上下文。
- 纸张在手机上取消桌面边缘、投影和多余外框。
- 实机测量：`documentElement.scrollWidth = 390`，`window.innerWidth = 390`。
- 发布渠道、CTA、任务字段和长标题均在 390px 正常换行。

## 3. 问卷所有因素的呈现审计

| 因素 | 视觉形式 | 交互与反馈 | 结论 |
|---|---|---|---|
| 研究标题 | 大号编辑型衬线文本，无默认输入框 | 聚焦时只出现一条底线 | 像文档标题，不像表单字段 |
| 原始研究目标 | 18px 正文、受控行宽 | 与标题保持明确层级 | 保留用户原意，建立信任 |
| 决策、目标、受众 | 唯一淡绿色任务面，三行定义列表 | 点击行内编辑，保存后重新校准提纲 | 研究北极星清晰且可操作 |
| 目标用户画像 | 稀疏文档段落，上方单一细线 | 更新时短暂出现非颜色边轨 | 无卡片噪声 |
| 假设 | H1 至 Hn 固定编号槽 | 文字自然换行 | 扫读效率高 |
| 受众筛选 | 轻量语义标签 | 多条件自然换行 | 保留筛选属性，不与普通正文混淆 |
| 访谈题目 | 单一连续列表、行间发丝线 | Hover 淡洗并向右 2px，更新时顺序生长 | 比独立卡片更像访谈提纲 |
| 每题目标 | 题目下方次级说明 | 与问题保持同一行块 | 研究意图可审查 |
| 成功标准 | 01 至 03 对齐编号 | 与问题编号共享语言 | 可量化标准被看见 |
| 受访者体验 | 文档章节式折叠入口 | 展开后呈现完整配置表单 | 高级配置不抢占默认流程 |
| 触达渠道 | 单一分组选择器 | 复选框、底色、真实后果文案 | 选择含义明确 |
| 发布 CTA | 黑色满宽主按钮 | 75ms 按下、150ms 回弹 | 结束动作确定、有触感 |

## 4. 动效与触感明细

| 状态 | 时长 | 位移 / 变化 | 目的 |
|---|---:|---|---|
| 手稿区块首次浮现 | 560ms | `translateY(10px)` 到 `0`，透明度到 1 | 形成“落到纸面”的浮现感 |
| 生成骨架分区成形 | 520ms | `translateY(7px)` 到 `0` | 显示结构正在被写出 |
| 写入光标 | 1450ms 循环 | 只改变透明度 | 唯一持续活动信号 |
| 问题批量更新 | 460ms | 每题相隔 45ms | 显示文档在生长 |
| 小控件按下 | 75ms | `scale(0.96)` | 立即确认手指动作 |
| 行选择按下 | 75ms | `scale(0.993)` | 大面积控件不显橡皮感 |
| 回弹 | 150ms | 回到原位 | 快进慢出，保持沉稳 |
| reduced motion | 0ms | 无动画、无位移，保留静态色调反馈 | 尊重系统辅助设置 |

Kimi 通过 CDP 设置 `prefers-reduced-motion: reduce` 后实测：

- `.tp-study-emerge`：`animation-name: none`
- `.tp-press`：`transition-duration: 0s`
- 所有内容保持可见，按压仍有静态明度反馈

## 8. 最终结论

在“从一句自然语言创建并完善研究问卷”这一明确任务里，Telepace 已经不再复制 Notion。
它保留了 Notion 最有价值的克制边界、连续文档和低噪声编辑，同时增加了 Notion 不具备的：

- 研究任务语义层
- 问卷就绪度
- AI 生成的结构化空间叙事
- 对话自动退场与可召回
- 更新内容的原位、可访问反馈
- 从研究内容自然走向受访者配置和发布的闭环

按照本报告预先固定的十维评分模型，最终为 **100 / 100**，并在限定任务的每个维度
高于 Notion 启发式参照。
