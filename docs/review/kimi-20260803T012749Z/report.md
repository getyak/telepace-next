# Telepace 全链路量化测评

> 测评时间：2026-08-03（Asia/Singapore）
>
> 测评方式：Kimi WebBridge Browser，使用真实浏览器、全新账号和真实登录态
>
> 测试研究：`2cf9d3e8-4802-432e-93f4-8056529dd068`
>
> 覆盖链路：注册/登录 → 空状态 → AI 创建研究 → 编辑 → 模拟 → 发布 → 受访者同意 → 真实文字访谈 → 洞察 → 报告 → 全局研究助手 → 移动端

## 结论

**生产就绪度：66 / 100，不建议面向真实客户正式发布。**

产品的视觉完成度、研究创建引导、模拟受访者和基于真实访谈生成洞察的能力已经很强；但研究详情与报告仍混入或完全使用演示数据，受访者端会暴露内部 JSON/UUID，创建超时后的重试还产生了同名重复草稿。这些问题直接破坏“研究数据可信”这一产品底线。

- 10 条用户故事中，9 条可以到达终态；“可信报告/交付”未通过。
- 用户故事可达性均分为 **75.1 / 100**。
- 因存在 3 个 P0 可信度问题，按生产硬门槛折算后的总分为 **66 / 100**。
- 当前最强体验是“模拟受访者”和“真实访谈洞察”；最弱体验是“报告”和“跨研究助手交付”。

- 90–100：可直接交付，只有轻微细节问题。
- 75–89：核心可用，需要有限修正。
- 60–74：能完成任务，但有明显风险或重要缺口。
- 40–59：勉强可用，关键环节不可靠。
- 0–39：任务失败或输出不可采信。

## 关键性能与等待感知

这些数据来自一次真实端到端运行，用于发现体验瓶颈，不等同于多样本性能基准。

| 动作 | 实测等待 | 用户感知 |
|---|---:|---|
| 登录页 DOMContentLoaded / load | 0.50 秒 / 1.07 秒 | 快 |
| 研究列表 DOMContentLoaded / load | 1.25 秒 / 1.57 秒 | 可接受 |
| 注册后进入研究列表 | 约 2.4 秒 | 可接受 |
| AI 第一次澄清 | 约 8.8 秒 | 偏慢，但有“正在思考”反馈 |
| 首次创建研究 | 超过 30 秒后超时 | 失败反馈明确，但打断信心 |
| 重试创建 | 约 35 秒 | 过慢，且产生重复草稿 |
| 模拟受访者 | 约 10 秒 | 结果价值足以部分抵消等待 |
| 发布并获得链接 | 约 2.7 秒 | 快 |
| 受访者首题出现 | 约 2.9 秒 | 可接受 |
| 访谈 AI 单回合 | 多数约 9–11 秒 | 连续多轮后明显拖沓 |
| 全局研究助手追问 | 约 34 秒后失败 | 高期待后无结果，负面感知强 |

建议目标：

- 创建研究 P95 ≤ 20 秒；超过 12 秒显示阶段与预计剩余时间。
- 访谈追问 P95 ≤ 6 秒；超过 3 秒先返回轻量确认语或流式首字。
- 研究助手简单证据检索 P95 ≤ 15 秒，并在执行预算不足时降级为直接读取当前研究洞察。

## P0：上线阻断问题

### P0-1 研究详情把演示数据呈现为当前研究的真实数据

新研究尚无访谈时，顶部指标正确显示 0/10，但同页已经显示：

- N=48 的满意度图表；
- N=24/14/10 的交叉表；
- 6 个与“电脑显示器”有关的英文受访者；
- `P-5003`、Dell UltraSharp、eye strain 等无关信息。

完成真实访谈后，这批固定数据仍和真实洞察并列出现。研究产品一旦让用户无法区分真实数据与演示数据，后续任何置信度、报告或建议都不可采信。

代码证据：

- `frontend/apps/app/src/app/[locale]/(app)/studies/[id]/page.tsx:542` 定义 `MOCK_RESPONSES`。
- 同文件 `:617` 无条件把它传给 `ResponseTable`。
- 同文件 `:640` 定义固定满意度分布，`:664` 固定 `baseN={48}`。

证据：[发布后的研究详情](./07-published-dashboard.png)、[真实洞察与固定数据混合](./11-grounded-insights.png)

修复要求：

1. 详情页只能消费当前 campaign 的真实 responses/metrics。
2. 零样本时显示空状态，绝不自动回退到 fixture。
3. 演示模式必须有显著、持续的“演示数据”标记，并与真实 workspace 隔离。

### P0-2 报告页完全忽略当前研究，始终生成静态英文报告

本次研究已经有 1 份真实访谈和 8 条中文洞察，但报告展示的是：

- “Speed to insight matters more than price”；
- “Voice-native interviews feel more natural”；
- `resp-001` 等 9 处无关受访者引用；
- 与当前新手引导研究完全无关的英文内容。

代码证据：

- `frontend/apps/app/src/lib/evidence-store.tsx:24` 导入 `buildMockEvidenceGraph`。
- 同文件 `:61` 对任何 `studyId` 都设置 mock graph。
- `frontend/apps/app/src/lib/mock-evidence.ts:101` 开始定义浏览器中看到的静态报告。

证据：[无关静态报告](./12-report-fake-data.png)

修复要求：

1. `EvidenceProvider` 改为读取当前 study 的真实 themes、insights、citations 和 transcripts。
2. 报告生成前校验所有 citation 的 `study_id/campaign_id` 一致。
3. 报告页显示样本量、生成时间、数据截止时间和可回溯原话。
4. 没有真实证据时显示“证据不足”，禁止使用 mock 兜底。

### P0-3 受访者会看到内部 JSON 协议和 `outline_item_id`

访谈中至少 3 次把以下内部结构直接显示成研究员问题：

```text
{"kind":"probe","outline_item_id":"…","text":"…"}
```

这既破坏访谈沉浸感，也暴露内部协议和实体标识。受访者可能把 JSON 当成问题回答，污染研究数据。

代码证据：

- `agents/interviewer/main.py:168` 只解析 `<action>` 或 JSON fenced code block。
- 同文件 `:170-175` 遇到裸 JSON 时把整段原文作为 `text`。
- `frontend/apps/app/src/app/[locale]/(public)/r/[campaignId]/page.tsx:318-325` 直接渲染后端 `result.text`。

证据：[受访者端裸 JSON](./09-raw-json-probe.png)

修复要求：

1. 后端首先尝试解析整段 JSON，再解析 tag/fence；只允许 schema 校验后的 `text` 出站。
2. WebSocket DTO 不应向客户端发送 `outline_item_id` 等非必要内部字段。
3. 前端增加最后一道协议检测：若文本是对象或包含内部字段，隐藏并上报，不得渲染。
4. 为裸 JSON、JSON fence、`<action>`、混合 prose、错误 JSON 补齐契约测试。

## P1：高优先级问题

### P1-1 创建超时后的重试不是幂等操作

前端 30 秒主动超时并提供“重试”，但后端原请求可能仍然完成。实测重试后，全局助手列出了两个同名研究：一个进行中 1/10，另一个草稿 0/10。

代码证据：

- `frontend/apps/app/src/lib/http.ts:31` 使用 30 秒默认超时。
- `frontend/apps/app/src/app/[locale]/(app)/studies/new/page.tsx:831-844` 重试时重新执行同一创建文本。
- `interfaces/rest_api/routers/campaigns.py:192-227` 创建接口没有 idempotency key 或请求去重。

修复：客户端生成稳定 `Idempotency-Key`，同一次创建及其重试复用；服务端按 `org_id + key` 返回首个结果，并允许超时后查询创建状态。

证据：[超时与重试入口](./04-create-timeout.png)

### P1-2 自适应追问与 6 题进度模型不一致

自适应追问本身质量高，但进度长时间停在“第 4 / 6 题”，即使 AI 已说“最后想问一下”。用户无法判断还要多久，可能中途离开。

修复：区分“主问题 4/6”和“本题追问 2”；进入下一 outline item 时单调递增；wrap-up 前强制校准为 6/6。

### P1-3 全局研究助手在简单限定任务上耗尽执行预算

助手能列出研究、检查进度、生成洞察、读取访谈，工具过程透明；但约 34 秒后返回英文：

> I reached the execution limit before I could verify completion.

它没有输出用户要求的 3 条原话证据。`agents/orchestrator/main.py:842` 的子任务只有 4 个 turn，复杂检索很容易在整理答案前耗尽。

修复：给证据检索提供直接聚合工具；保留最后一个 turn 专用于答复；预算将耗尽时基于已取回数据生成部分答案，而不是只返回系统错误。

证据：[研究助手执行未完成](./13-assistant-followup.png)

### P1-4 中文受访者页面的文档语言和标题错误

`/zh/r/...` 页面内容为中文，但实测 `<html lang="en">`，页面标题为英文营销标题。屏幕阅读器、翻译工具和浏览器语言感知都会受到影响。

修复：让 public respondent layout 根据 route locale 生成 metadata，并加入 `/zh/r/...` 的 `<html lang="zh">` 和中文标题端到端测试。

### P1-5 研究完成后“访谈时长中位数”仍为空

完成 1 份访谈后，研究详情的完成数和洞察数已更新，但时长仍为 `—`。这削弱运营监控完整性，也与完成页确认“11 条回答已提交”不一致。

## P2：UI、细节与体验优化

### 可访问性与移动端

- 全局研究助手关闭时，`role="dialog"` 仍留在 DOM/可访问性树中，没有 `aria-hidden` 或 `inert`。代码位于 `frontend/apps/app/src/components/agent/AgentDock.tsx:90-103`。
- 关闭态移动端顶部仍可看到轻微“研究助手”残影；打开态背景正文透过半透明面板，中文密集内容的对比度不足。
- 报告在 390×844 下没有水平溢出，正文宽度适配良好，这是明确的正向结果。

建议：关闭时不渲染 `<aside>`，或同时设置 `hidden/inert/aria-hidden`；移动端使用不透明背景，桌面端再保留材质透明感。

证据：[移动报告与助手](./14-mobile-report.png)、[移动端关闭态](./15-mobile-report-closed.png)

### 国际化与文案

- 中文报告夹杂大量英文，并出现原始 key `app.report.confidence`。
- 研究助手的执行失败文案是英文，且暴露 8 位 run id；对普通用户没有行动建议。
- 受访者同意页说明清楚，但缺少可见的隐私详情/数据用途链接。

### 版式细节

- 创建页留白和左右栏节奏成熟，但超长研究标题占三行，压缩了首屏有效信息。
- 折叠后的竖排“设计聊天”可发现性偏弱，在窄屏更像装饰文字。
- 报告页移动端导出按钮优先级不清；PDF 是禁用状态但没有解释何时可用。

## 做得好的部分

### UI 与品牌感

- 暖纸色、衬线标题、鼠尾草绿和陶土色形成一致且有辨识度的研究工具视觉语言。
- 登录、空状态、发布页、同意页、模拟弹窗和洞察卡片的层级都清楚。
- 关键按钮文案具体，例如“发布并获取链接”“用文字开始”，没有抽象 CTA。
- 加载、思考、起草、超时和重试均有可见状态，不会让用户误以为页面冻结。

### AI 研究体验

- 创建前先补齐“受访者是谁”，澄清问题与研究决策直接相关。
- 生成方案覆盖 persona、假设、筛选、提纲、成功标准，结构完整。
- 模拟受访者能提前暴露产品摩擦，且回答不是模板化赞美。
- 真实访谈会引用前文继续追问，例如追问“为什么继续而没有关闭”，研究员感知明显优于静态问卷。
- 真实洞察与原话一致，并给出 85%–95% 的置信度层次；一旦移除演示数据污染，这部分已接近可交付水平。

证据：[研究方案完成态](./05-study-ready.png)、[模拟受访者](./06-simulate.png)、[真实洞察](./11-grounded-insights.png)

## 建议的修复顺序

1. **可信数据隔离**：移除详情和报告的 mock fallback，所有卡片绑定当前 campaign。
2. **访谈协议边界**：后端严格解析/校验结构化动作，客户端只接收展示文本。
3. **创建幂等性**：超时重试复用 idempotency key，并提供“正在后台创建”的可恢复状态。
4. **进度语义**：主问题与追问分层显示，进度必须单调且最终到 6/6。
5. **助手完成策略**：增加直接证据检索工具、预算预留和部分结果降级。
6. **语言与可访问性**：修正 respondent metadata、隐藏态 dialog、移动端不透明度和 i18n key。
7. **性能优化**：流式返回首字，缓存研究上下文，记录各阶段 P50/P95。

## 发布验收门槛

以下条件全部通过后，建议重新做一轮 Kimi WebBridge 回归测评：

- 新建 0 访谈研究的详情页不出现任何 respondent、图表或样本量。
- 完成 1 次访谈后，详情、洞察、报告只出现该访谈的数据和原话。
- 报告中的每个引用都能回到当前 campaign 的具体 transcript turn。
- 连续运行 30 次文字访谈，用户界面 0 次出现 JSON、UUID、协议字段或系统提示词。
- 模拟 30 秒客户端超时后点击重试，最终只产生 1 个 campaign。
- 追问阶段显示“主问题 x/6 · 追问 y”，进度不回退、不长期停滞。
- 研究助手能在 15 秒目标内返回 3 条带原话的当前研究证据；预算不足时仍返回可用的部分结果。
- `/zh/r/...` 的 `<html lang>`、标题和可见文案均为中文。
- 助手关闭后不在可访问性树中；390 px 宽度下无内容残影、横向溢出或低对比正文。
- 创建研究和访谈追问达到前述 P95 目标，并有可观测指标。
